# Vessel data layout

Each vessel has its own folder under `data/vessels/<vessel-name>/`:

```text
<vessel-name>/
├── mesh/                  3D model of the vessel (obj/stl/glb/blend)
└── hydro/
    ├── veres/             ShipX/VERES (2D strip theory) input/output -- maneuvering
    └── wamit/              WAMIT (3D panel method) input/output -- station-keeping
        ├── mesh/           WAMIT mesh (<vessel>.gdf) + reference view images
        ├── inputs/         WAMIT control files as actually run: <vessel>.cfg, .frc, .pot
        ├── outputs/        Raw WAMIT run output -- see below
        ├── processed/      Generated files -- see below, do not edit by hand
        └── plots/          Plots (PDF) generated from the processed vessel struct
```

## 3D Model

`mesh/` holds the vessel's 3D geometry for reference and visualization
(`.obj`/`.stl`/`.glb`/`.blend`), independent of either hydrodynamic analysis
below. This is not the same as `hydro/wamit/mesh/`, which holds the
solver-specific panel mesh (`<vessel>.gdf`) WAMIT is actually run against.

## Stationkeeping

`hydro/wamit/` holds WAMIT (3D panel method) potential-flow data: added
mass/damping, motion/force RAOs, mean drift forces, and the retardation
state-space models fitted from them. This is what feeds station-keeping /
DP analysis.

- **`wamit/inputs/`** -- WAMIT control files as actually run: `<vessel>.cfg`,
  `.frc`, `.pot`.
- **`wamit/mesh/`** -- WAMIT panel mesh (`<vessel>.gdf`) + reference view
  images.
- **`wamit/outputs/`** -- Raw WAMIT run output. Drop the files WAMIT produces
  here after running it with the control files from `wamit/inputs/`: the
  numeric output files `<vessel>.1`/`.2`/`.3`/`.4`/`.8`/`.9`, plus `.hst`,
  `.out`, `.mat`. This folder is the source of truth for a WAMIT run and is
  never modified by any script.
- **`wamit/processed/`** -- Generated by `scripts/wamit_v7_to_v6.py --walk`.
  Don't edit these by hand -- rerun the script instead:
  - `inputs/*.pot` / `*.frc` converted from WAMIT v7.x to v6 format (plus a
    v6 `.cfg` snippet), since the MSS toolbox parsers expect v6 output.
  - `outputs/<vessel>.N` numeric files copied over with the `NUMHDR=1`
    banner line WAMIT writes stripped (older MSS parsers can't read it). If
    WAMIT wasn't run with periods `-1`/`0` (zero-/infinite-frequency solves,
    required by `wamit2vessel`), zero-/infinite-frequency rows are
    synthesized instead (nearest computed period for added mass, zero
    damping) -- watch the console warnings, this is an approximation, not a
    real WAMIT solve.
  - `outputs/<vessel>.out` copied over, with 2 placeholder run-log lines
    added when the synthesized rows above were needed, so the frequency
    count MSS derives from `.out` matches the (possibly synthesized) `.1`
    data.

  This is the folder MATLAB/Octave scripts (e.g. `voyager_station_keeping.m`)
  point `wamit2vessel`/`vessel2ss` at.
- **`wamit/plots/`** -- Plots (PDF) generated from the processed vessel
  struct.

Parsing the WAMIT output into an MSS vessel struct and fitting a
state-space model requires the [MSS toolbox](https://github.com/cybergalactic/MSS),
vendored as the `external/MSS` git submodule. If it's empty, run:

```bash
git submodule update --init external/MSS
```

## Maneuvering

`hydro/veres/` holds ShipX/VERES (2D strip theory) input/output data, used
for maneuvering analysis.
